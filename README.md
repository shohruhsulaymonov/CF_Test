# Тренажёр экзаменационных вопросов

Сайт по ТЗ «платформа тренировки экзаменационных вопросов (v2)». Главный набор — `files/CorpFin_300.xlsx` (300 вопросов, 20 тем).

## Запуск

Сайт: **https://corp-finances.firebaseapp.com** (Firebase Hosting). Сборка не нужна. Старый адрес на GitHub Pages и `corp-finances.web.app` переводят сюда (`siteUrl` в `config.js`).

Публикация — из корня репозитория (нужен Node.js; один раз выполнить `npx firebase-tools login`):

```
npx firebase-tools deploy --only hosting      # сайт
npx firebase-tools deploy --only firestore    # правила и индексы Firestore
```

Локально: `python -m http.server` в корне и `http://localhost:8000/` (вход через Google из файла `index.html` не работает; с `firebase: null` в `config.js` можно открыть и файл).

Без Firebase — вход по имени, администратор — имя из `assets/js/config.js` (`adminNames`, по умолчанию «Админ»; **поменяйте его** перед публикацией). С Firebase — вход через Google (см. ниже).

## Наборы вопросов

Каждый набор — файл `sets/<id>.js`, список файлов — `sets/manifest.js`. Набор `primarySetId` из `config.js` открывается на главной, остальные — в разделе «Другие наборы». Все функции (4 режима, настройки, закладки, свои наборы, история, аналитика, источники) работают для любого набора одинаково.

**Добавить или обновить набор:**

```
python tools/build_set.py files/CorpFin_300.xlsx --id corpfin --title "Корпоративные финансы"
python tools/build_set.py path/to/Macro.xlsx --id macro --title "Макроэкономика" --description "..."
```

Скрипт (нужен `openpyxl`) пишет `sets/<id>.js` и обновляет `sets/manifest.js`. После обновления страницы изменения применяются по правилам ТЗ §3: ключ — №, новые строки добавляются, изменённые обновляются, пропавшие скрываются; строки с ошибками пропускаются и видны в админ-панели («Импорт и наборы» → «Журнал импорта»).

**Сменить главный набор:** поменяйте `primarySetId` в `assets/js/config.js`.
**Убрать набор:** удалите его файл из `sets/` и строку из `sets/manifest.js`.

Администратор может загрузить Excel и прямо в браузере (обновить набор с предпросмотром или создать новый), а затем скачать файл набора `.js`, чтобы добавить его в репозиторий.

Формат Excel — как у `CorpFin_300.xlsx`: лист «Лист1» (или первый лист) со столбцами №, Вопрос, A, B, C, D, Правильный вариант, Категория, Подсказка, Сложность (1–5), Мнемоника; необязательный лист «Источники» (№, Источник, Где используется, Ссылка).

## Firebase: вход через Google, все данные в облаке

Без настройки вход по имени и всё хранится только в браузере. С Firebase (бесплатный тариф Spark) пользователи входят через Google-аккаунт, а все данные хранятся в Firestore: игры, закладки, свои наборы, настройки режимов, сообщения об ошибках и наборы вопросов с правками админа. В админ-панели появляется «Статистика»: кто пользуется сайтом, активность, верные и неверные ответы по темам и вопросам, популярные режимы — в целом и по каждому пользователю. Браузер хранит копию для работы без интернета: изменения ждут в очереди и отправляются при появлении связи.

1. https://console.firebase.google.com → создайте проект → добавьте Web app (`</>`) и скопируйте объект `firebaseConfig`.
2. **Build → Firestore Database** → Create database (production mode).
3. **Build → Authentication → Sign-in method**: включите **Google**. На **Settings → Authorized domains** добавьте `shohruhsulaymonov.github.io`.
4. **Правила**: в `firestore.rules` впишите Google-почту админа в `isAdmin()` и выполните `npx firebase-tools deploy --only firestore` (или вставьте файл в Firestore → Rules → Publish).
5. **Индексы**: та же команда создаёт три индекса из `firestore.indexes.json` (коллекции `games`, `reports`, `notifications`, поля `user_id` и `_ts`). Вручную — Firestore → Indexes → Composite. Без индексов сайт работает, но каждый раз загружает всю историю пользователя (в консоли браузера будет ссылка на создание индекса).
6. В `assets/js/config.js`: `firebase: { apiKey, authDomain, projectId, appId }` и `adminEmails: ['<почта админа>']`.

При первом входе пользователь указывает имя — его видит админ в «Статистике» рядом с почтой. Админ входит через Google так же, как все; админ-панель открывается для почт из `adminEmails`. Если на устройстве осталась история прежнего входа по имени, сайт предложит перенести её в аккаунт. Каждый пользователь читает только свои данные (это проверяют правила Firestore), админ — всё. Ключ `apiKey` не секретный: доступ ограничивают правила. Вход через Google работает на сайте (https://), а не при открытии `index.html` из файла.

Что где хранится:
- **Игры, закладки, свои наборы, настройки режимов** — в аккаунте пользователя, доступны на любом устройстве. Если одно и то же меняли на двух устройствах одновременно, сохраняется последнее изменение.
- **Наборы вопросов** — правки, скрытие вопросов, категории и загрузка Excel в админ-панели публикуются на сервере, и все пользователи получают их при следующем открытии сайта (или возвращении на вкладку). Скачивать файл набора и отправлять его в GitHub больше не обязательно. Файлы `sets/*.js` по-прежнему работают: обновлённый файл применяется у всех сразу, а на сервер попадает при следующем входе админа.
- **Сообщения об ошибках и уведомления** — смена статуса сообщения приходит автору на любом устройстве.

## Ограничения

- Без Firebase данные (пользователи, игры, закладки, отчёты, правки админа) хранятся **в браузере** каждого пользователя: админ видит отчёты и статистику только с этого же браузера. Резервная копия — в админ-панели.
- Требование «клиент не получает правильный ответ до ответа» (ТЗ §12) без сервера не выполнимо: ответы есть в файле набора.
- Для общего хранения нужен сервер (по ТЗ — Node.js + PostgreSQL/SQLite); весь доступ к данным собран в `store.js`, его можно заменить вызовами API.
