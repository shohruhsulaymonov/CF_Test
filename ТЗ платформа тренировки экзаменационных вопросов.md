# ТЗ: платформа тренировки экзаменационных вопросов

Oct 20, 2026 · @Ash

## 1. Обзор

Платформа для подготовки к экзаменам: пользователь тренируется в четырёх игровых режимах, после каждой игры получает разбор результатов. Весь интерфейс, вопросы, подсказки, мнемоники и сообщения обратной связи — на русском языке.

Пользователи: студенты и самостоятельно готовящиеся к экзаменам; администратор, который управляет контентом и отчётами об ошибках.

## 2. Объём работ

В версии 1 входят четыре режима:

1. **Карточки** — режим «флешкарт» в духе Quizlet: лицевая сторона вопрос, оборотная ответ, оценка «знаю / не знаю».
2. **Доска** — режим в духе Bamboozle: сетка скрытых плиток, за каждой вопрос.
3. **Своя игра** — режим в духе «Jeopardy» / SIGame: категории и столбцы с ценой вопроса.
4. **Викторина** — режим в духе Kahoot: вопрос с вариантами ответа и таймером.

Вне версии 1: многопользовательский режим в реальном времени, мобильное приложение, оплата, импорт файлов из сторонних сервисов.

## 3. Модель данных

| Сущность | Ключевые поля | Связи |
| --- | --- | --- |
| Вопрос (question) | id, текст, ответ, категория\_id, уровень (1–5), подсказка, мнемоника, ссылка\_на\_материал, создан\_в | принадлежит категории |
| Категория (category) | id, название, предмет | содержит вопросы |
| Игра (game) | id, пользователь\_id, режим, начало, конец, итоговый\_процент | содержит ответы |
| Ответ (answer) | id, игра\_id, вопрос\_id, верно (да/нет), время\_ответа\_мс | ссылается на вопрос |
| Пользователь (user) | id, имя, роль (студент / админ), создан\_в | имеет игры |
| Отчёт об ошибке (report) | id, вопрос\_id, пользователь\_id, комментарий, статус | ссылается на вопрос |
| Шаблон сообщения (feedback\_template) | id, тип (tier / category), диапазон\_процентов или категория, текст | используется в итогах игры |

Каждая игра сохраняет агрегаты по уровням и категориям, чтобы обратная связь не пересчитывала историю заново.

## 4. Игровые режимы

**4.1 Карточки.** Колода выбирается по категории или уровню. Карточка переворачивается по нажатию. Пользователь отмечает «знаю» или «не знаю». Неизвестные карточки возвращаются в колоду чаще. Ответ записывается как верный или неверный.

**4.2 Доска.** Сетка плиток N×M, за каждой плиткой скрыт вопрос. Выбор плитки открывает вопрос, ответ засчитывается, плитка закрывается. Игра заканчивается, когда все плитки открыты.

**4.3 Своя игра.** Категории в столбцах, стоимость вопроса растёт по строкам и соответствует уровню 1–5. Выбранный вопрос открывается в окне, пользователь отвечает и получает или теряет очки. Очки начисляются по стоимости: уровень 1 — 100, уровень 5 — 500.

**4.4 Викторина.** Вопрос с 4 вариантами, таймер 20 секунд. Скорость влияет на бонус: верный ответ за первые 5 секунд даёт полный балл, дальше балл убывает линейно до половины к концу таймера. Неверный или просроченный ответ — ноль.

Во всех режимах ответы пишутся в таблицу ответов с привязкой к вопросу и уровню. По окончании игры запускается движок обратной связи (раздел 6).

## 6. Движок обратной связи

Движок запускается в конце каждой игры и выдаёт одно сообщение по каждому применимому правилу.

**Шаг 1. Общий результат.** Процент верных ответов за игру переводится в уровень (tier):

| Tier | Диапазон, % верных |
| --- | --- |
| 1 | 0–20 |
| 2 | 21–40 |
| 3 | 41–60 |
| 4 | 61–80 |
| 5 | 81–100 |

Из пула 10 шаблонов соответствующего tier выбирается один, исключая шаблоны, показанные пользователю в последних 5 играх.

**Шаг 2. Слабая категория.** Категория считается слабой, если в игре по ней было не менее 3 ответов и верных меньше 50%. Выбирается категория с наименьшим процентом; при равенстве — с большим числом ошибок. Выбирается один шаблон из 10 шаблонов категорий, подставляется название категории.

**Шаг 3. Слабый уровень.** Если по одному уровню сложности верных меньше 50% при не менее 3 ответах, в шаблон категории подставляется `{уровень}`. Если слабой категории нет, но есть слабый уровень, выбирается шаблон категории и подставляется уровень, а название категории берётся из самой слабой категории игры.

**Шаг 4. Ничего слабого нет.** Если ни одна категория и ни один уровень не слабые, выводится только сообщение tier.

**Шаг 5. Сохранение.** Выбранные шаблоны и итоговые агрегаты сохраняются в игре. Обратная связь не пересчитывается при повторном открытии.

## 7. Библиотека сообщений

Сообщения заранее написаны и хранятся в базе. Во время игры ИИ не участвует: движок выбирает готовый шаблон по правилам раздела 6. Тон нейтральный: одно наблюдение, без обращения и без прямых рекомендаций. Плейсхолдеры: `{процент}`, `{категория}`, `{уровень}`.

**Tier 1 (0–20%)**

1. Верных ответов в этой игре мало: {процент}%.
2. Большинство карточек осталось без ответа, и это видно по результату.
3. Результат ниже {процент}%. Заметного прогресса за игру не видно.
4. Вопросы этого раунда оказались сильнее. Счёт отражает это.
5. «Не знаю» в этой игре было ответом чаще, чем верный вариант.
6. Такой результат обычно бывает при первом знакомстве с материалом.
7. Из всех вопросов верными оказались единицы.
8. Игра прошла без заметного результата: {процент}% верных ответов.
9. Пока материал не закреплён, результат будет таким же.
10. Раунд закончился без знаний, которые можно было бы засчитать.

**Tier 2 (21–40%)**

1. {процент}% верных ответов. Первые верные ответы есть, но их пока немного.
2. Примерно каждый третий ответ верный.
3. Знаний больше, чем показано в этой игре, но часть из них не выходит наружу.
4. Угадывание дало часть баллов, и его в этом результате заметно больше, чем знаний.
5. Ответы выбираются медленно, и это видно по счёту.
6. Ошибки в этой игре были уверенными.
7. Результат выше прошлого раза или, по крайней мере, не ниже.
8. Уровни 1–2 в целом освоены, дальше пробелы.
9. Игра закончилась на уровне {процент}%: заметных сдвигов нет.
10. До среднего результата осталось немного.

**Tier 3 (41–60%)**

1. Половина ответов верная. Средний результат без выраженной динамики.
2. Простые вопросы засчитаны, сложные нет.
3. Ответы то верные, то неверные, без явной закономерности.
4. Заметного провала нет, но и уверенного результата тоже.
5. Вторая половина ответов приходится на уровни, которые в игре встречались реже.
6. Результат зависит от конкретных вопросов, а не от общего уровня.
7. Около половины пути пройдено.
8. Фундамент есть, но детали пока теряются.
9. Результат ниже предыдущих игр или на том же уровне.
10. Средний результат: {процент}% верных ответов.

**Tier 4 (61–80%)**

1. Результат хороший, но не стабильный.
2. Основное известно, детали пока нет.
3. Несколько ошибок пришлись на вопросы, которые часто встречаются на экзаменах.
4. Почти все ответы верные, угадывания почти нет.
5. Ошибки на высоких уровнях заметны больше остальных.
6. Скорость ответов не мешает точности.
7. Часть ошибок связана с невнимательностью: вопрос прочитан не полностью.
8. Знаний больше, чем показывает результат.
9. Сложные вопросы почти закрыты, остались отдельные пробелы.
10. Результат близок к высокому, но пока не стабилен.

**Tier 5 (81–100%)**

1. Почти все ответы верные. Одна ошибка на уровне 5 осталась.
2. Результат высокий, но одна игра не показывает устойчивости.
3. Счёт соответствует хорошей подготовке, а не случайному совпадению.
4. Почти все вопросы засчитаны.
5. Главный риск сейчас — уверенность в ответах без перепроверки.
6. Результат стабилен для одной игры; следующая покажет, так ли это.
7. Высокий результат, и сложные вопросы тоже засчитаны.
8. Почти полный результат. Сложность можно повысить.
9. Почти весь набор вопросов закрыт.
10. Материал освоен на уровне, который показывает эта игра.

**Категории (любой tier, подставляются `{категория}` и `{уровень}`)**

1. По теме «{категория}» верных ответов меньше, чем ошибок.
2. В теме «{категория}» пробелы повторяются.
3. По теме «{категория}» результат ниже остальных.
4. Тема «{категория}» дала больше всего ошибок в этой игре.
5. Ошибки по теме «{категория}» сосредоточены на уровне {уровень}.
6. Тема «{категория}» в этой игре почти не засчитана.
7. По теме «{категория}» ответы неуверенные.
8. В теме «{категория}» часть ошибок повторяется из раунда в раунд.
9. Тема «{категория}» по-прежнему слабая.
10. По теме «{категория}» на уровне {уровень} ошибок больше, чем верных ответов.

## 8. Аналитика

Пользователь видит четыре блока:

- **Чаще всего ошибочные вопросы** — таблица из 20 строк: вопрос, категория, уровень, число ошибок, доля ошибок, дата последней ошибки.
- **Активность по дням** — линейный график числа ответов за последние 90 дней, с отметкой дней без игр.
- **Режимы игры** — столбчатая диаграмма: число игр по каждому из четырёх режимов за период.
- **Динамика по категориям** — процент верных ответов по категориям по неделям.

Период по умолчанию — 30 дней, переключатель: 7 / 30 / 90 дней / всё время.

## 9. Админ-панель и отчёты об ошибках

- **Очередь проверки.** Новые вопросы от ИИ со статусами «на проверке», «одобрен», «отклонён». Редактирование ответа, подсказки, мнемоники и уровня до публикации.
- **Категории.** Создание, переименование, объединение. Удаление только для категорий без вопросов.
- **Отчёты пользователей.** Кнопка «Сообщить об ошибке» в каждом режиме. Отчёт содержит вопрос, комментарий и статус: «новый», «в работе», «исправлен», «отклонён».
- **Повторная генерация.** Для одного вопроса: новый ответ, подсказка или мнемоника с сохранением старой версии.
- **Пользователи.** Список, роли, просмотр активности. Без доступа к содержимому личных заметок.

Доступ к админ-панели только для роли «админ».

## 10. Нефункциональные требования и стек

- **Язык интерфейса и контента:** русский. Даты в формате ДД.ММ.ГГГГ, числа в русской локали.
- **Производительность:** открытие карточки или вопроса менее 300 мс при 1 000 вопросов в базе; формирование итогов игры менее 1 с.
- **Безопасность:** пароли хранятся в виде хэша, доступ к админ-панели только по роли, ключи API ИИ не попадают в клиентский код.
- **Доступность:** адаптивная вёрстка для ноутбука и планшета; минимальный размер шрифта 16 px в игровых режимах.
- **Стек (предварительно):** веб-клиент на React, сервер на Node.js или Python, база данных PostgreSQL, очередь генерации вопросов в фоновом режиме.
- **Хостинг:** одна виртуальная машина или платформа с управляемой базой; резервное копирование базы ежедневно.

Стек требует подтверждения до начала разработки.

## 10а. Пользователи, повторы и наборы вопросов

**Идентификация.** Пользователь при первом входе вводит имя. Имя уникально (сравнение без учёта регистра и пробелов в начале и конце), длина от 2 до 30 символов. Повторный вход — по тому же имени; браузер запоминает имя, чтобы не вводить его каждый раз. Пароля в версии 1 нет (см. открытые вопросы).

**Настройки по каждому режиму.** Каждый из четырёх режимов хранит свои настройки отдельно:

| Настройка | Значение по умолчанию | Описание |
| --- | --- | --- |
| Повторять вопросы | да | Если выключено, вопросы, на которые пользователь уже ответил в этом режиме, не появляются, пока не закончится весь диапазон |
| Диапазон от | 1 | Номер первого вопроса в диапазоне, целое число 1–300 |
| Диапазон до | 300 | Номер последнего вопроса в диапазоне, целое число 1–300, не меньше «от» |

Диапазон ограничивает выборку номерами вопросов в общей базе. Если в диапазоне меньше вопросов, чем задано, игра использует все доступные вопросы диапазона и показывает пользователю сообщение.

**Правило «без повторов».** Учитывается любой ответ, верный или неверный, в режиме, для которого включено правило. Ответы из других режимов не влияют. Когда все вопросы диапазона отвечены, список сбрасывается, и игра начинается заново с сообщением «Все вопросы пройдены, начинаем сначала». Ответы в истории сохраняются, сбрасывается только список для выборки.

**Сохранённые наборы.** Пользователь сохраняет набор: название, режим и список конкретных вопросов. Каждая игра с этим набором использует те же вопросы. Настройки повторов и диапазона на сохранённый набор не действуют. Если администратор удалит вопрос, он исчезает из набора, и пользователь получает уведомление. Редактирование текста вопроса набор не меняет.

**Закладки вопросов.** Пользователь ставит закладку на отдельный вопрос в любом режиме или в карточке ответа. Закладки хранятся по пользователю, а не по режиму: один вопрос можно добавить в закладки из любой игры. Список закладок открывается отдельным экраном, где вопрос можно сразу открыть для повтора в режиме «Карточки». Снятие закладки не удаляет историю ответов.

**Набор из закладок.** Из списка закладок пользователь выбирает вопросы и создаёт сохранённый набор. Набор создаётся по тем же правилам, что и любой сохранённый набор: состав фиксирован, и игра с ним всегда использует те же вопросы. Один вопрос может входить в несколько наборов. Удаление закладки не меняет уже созданные наборы.

**Дополнительные таблицы.**

- `bookmark`: user\_id, вопрос\_id, создана\_в (уникальная пара user\_id + вопрос\_id).
- `saved_set_item`: набор\_id, вопрос\_id, позиция (связь наборов с вопросами, заменяет список в `saved_set`).

**Хранение данных.**

- `user`: id, имя (уникальное), создан\_в.
- `mode_settings`: user\_id, режим, повторять (да/нет), диапазон\_от, диапазон\_до.
- `saved_set`: id, user\_id, название, режим, список\_вопросов (упорядоченный), создан\_в.
- Выборка без повторов вычисляется по таблице ответов: вопросы режима пользователя, на которые есть хотя бы один ответ после последнего сброса.

**Открытые вопросы этого раздела:**

- [ ] Достаточно ли имени без пароля, или нужен простой PIN, чтобы другой человек не вошёл под чужим именем?
- [ ] Учитывать ли для правила «без повторов» только верные ответы?
- [ ] Порядок вопросов в сохранённом наборе фиксированный или перемешивается при каждой игре?
