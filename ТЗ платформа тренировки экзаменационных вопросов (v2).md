# ТЗ: платформа тренировки экзаменационных вопросов (v2)

20.10.2026 · @Ash

Версия 2 заменяет v1. Исходный файл не изменён. Список изменений — в приложении А. Всё, что принято по умолчанию без подтверждения, помечено «(допущение)» и собрано в разделе 14.

## 1. Обзор

Платформа для подготовки к экзамену по корпоративным финансам: пользователь тренируется в четырёх игровых режимах, после каждой игры получает разбор результатов. Интерфейс, вопросы, подсказки, мнемоники и сообщения обратной связи — на русском языке.

Пользователи: студенты и самостоятельно готовящиеся к экзамену; администратор, который загружает вопросы и разбирает отчёты об ошибках.

## 2. Объём работ

Версия 1:

1. **Карточки** — флешкарты в духе Quizlet: вопрос, переворот, оценка «знаю / не знаю».
2. **Доска** — сетка скрытых плиток, за каждой вопрос (в духе Bamboozle).
3. **Своя игра** — категории в столбцах, цена вопроса по сложности (в духе Jeopardy / SIGame).
4. **Викторина** — вопрос с таймером, баллы за скорость (в духе Kahoot).

Вне версии 1: ИИ-генерация вопросов и её очередь проверки, многопользовательский режим в реальном времени, мобильное приложение, оплата, импорт из сторонних сервисов, пароли и PIN.

Названия сервисов выше описывают механику; в интерфейсе они не используются.

## 3. Источник контента и импорт

Единственный источник вопросов — файл `files/CorpFin_300.xlsx`. ИИ в приложении не участвует.

**Лист «Лист1»** — 300 строк, столбцы по порядку: № (1–300), Вопросы, Вариант A, B, C, D, Правильный Вариант (буква A–D), Категория Вопроса, Подсказка, Сложность (число), Мнемоника.

**Лист «Источники»** — 20 строк: №, источник, где используется, ссылка. Выводится на экране «Источники» (только чтение).

**Правила импорта** (админ-панель, раздел 11):

- Перед применением показывается предпросмотр: сколько вопросов добавится, изменится, будет скрыто.
- Ключ строки — №. Существующий № обновляется, новый добавляется. № пропавший из файла скрывается (мягкое удаление), а не стирается.
- Проверки: все четыре варианта непусты и различаются между собой; правильный вариант — одна из букв A–D; сложность — целое 1–5; категория непуста; № уникален. Строка с ошибкой не импортируется, файл не отклоняется целиком, ошибки выводятся списком.
- Категории создаются автоматически по названию (без учёта регистра и пробелов по краям).
- Подсказка и мнемоника необязательны; пустые не выводятся.

**Свойства текущего набора** (важны для игры):

- Сложность в файле только 2, 3 и 4 (195 / 93 / 12 вопросов); уровней 1 и 5 нет. Уровень 4 почти не встречается: по одному вопросу в большинстве категорий.
- 20 категорий, от 2 до 34 вопросов.
- Правильный вариант распределён по буквам поровну (по 75), но в 76% случаев он самый длинный. Чтобы это не работало как подсказка, порядок вариантов при показе перемешивается (раздел 7). Рекомендуется сократить разрыв в длине вариантов в самом файле; на логику приложения это не влияет.

## 4. Модель данных

| Сущность | Поля |
| --- | --- |
| `question` | id, `number` (№ из файла, уникален), текст, `option_a`…`option_d`, `correct` (A–D), `category_id`, `level` (1–5), `hint`, `mnemonic`, `updated_at`, `deleted_at` |
| `category` | id, название (уникально) |
| `source` | id, номер, название, где используется, ссылка |
| `user` | id, имя (как введено), `name_key` (нормализованное, уникально), `created_at`, `last_seen_at` |
| `game` | id, `user_id`, `mode`, `started_at`, `finished_at`, `set_id` (null или сохранённый набор), `score` (очки, режимы с очками), `percent` (итоговый %) |
| `answer` | id, `game_id`, `question_id`, `selected` (A–D, null — нет ответа или оценка карточки), `correct` (да/нет), `time_ms`, `points`, `answered_at`, `level_at_answer`, `category_id_at_answer`, `is_repeat` |
| `game_aggregate` | `game_id`, `scope` (level / category), `key` (уровень или category_id), `answers`, `correct` |
| `game_feedback` | `game_id`, `kind` (tier / category / level), `template_id`, `text` (готовый текст после подстановки), `params` (JSON) |
| `feedback_template` | id, `kind` (tier / category / level), `tier` (1–5 или null), `text`, `requires` (условие применимости или пусто) |
| `mode_settings` | `user_id`, `mode`, `repeat` (да/нет), `range_from`, `range_to`, `category_ids` (null = все), `levels` (null = все), `active_set_id` (null), `cycle_started_at` |
| `saved_set` | id, `user_id`, название, режим, `created_at` |
| `saved_set_item` | `set_id`, `question_id`, `position` |
| `bookmark` | `user_id`, `question_id`, `created_at` (уникальная пара) |
| `report` | id, `question_id`, `user_id`, комментарий, статус (новый / в работе / исправлен / отклонён), `created_at`, `admin_note` |
| `notification` | id, `user_id`, текст, `created_at`, `read_at` |

Пояснения:

- `level_at_answer` и `category_id_at_answer` — копии на момент ответа: правка вопроса администратором не переписывает историю и итоги.
- `game_aggregate` и `game_feedback` заполняются один раз в конце игры (раздел 8). Итоги при повторном открытии не пересчитываются.
- Удаление вопроса — мягкое (`deleted_at`). Ответы, закладки и отчёты сохраняются. Из сохранённых наборов вопрос исчезает, пользователь получает `notification`.
- Хранение ответов в игре с «повторами» (Карточки): `is_repeat` отмечает повторные показы карточки в одной игре; в процент и агрегаты они не входят.

## 5. Пользователи и вход

- Вход только по имени, без пароля и PIN (решение заказчика).
- Имя: 2–30 символов; уникально без учёта регистра, пробелов по краям и различия «е/ё» (`name_key`).
- Одно поле «Ваше имя». Если такого имени нет, показывается подтверждение «Создать профиль «X»?» (защита от опечатки). Если есть — вход в этот профиль.
- Браузер запоминает имя (localStorage), повторный ввод не нужен.
- Роли: «студент» и «админ». Админ определяется списком имён в конфигурации сервера (`ADMIN_NAMES`). Эти имена не создаются через обычный вход и не показываются в интерфейсе.
- **Принятый риск:** любой, кто знает чужое имя (включая админа), может войти под ним. Для админ-панели это значит, что её защита — только секретность имени админа. Срок пересмотра: до выхода за пределы известной группы пользователей.

## 6. Выбор вопросов

**По умолчанию игра использует все 300 вопросов.** Пользователь может сузить выбор для каждого режима отдельно.

**Пул вопросов режима** = вопросы, одновременно удовлетворяющие всем заданным условиям:

| Настройка | По умолчанию | Описание |
| --- | --- | --- |
| Диапазон от / до | 1 / 300 | по № вопроса, целые 1–300, «до» не меньше «от» |
| Категории | все | один или несколько вариантов |
| Сложность | все | один или несколько уровней, имеющихся в базе |
| Повторять вопросы | да | при «нет» вопросы, уже отвеченные в этом режиме, не появляются, пока не пройден весь пул |

**Выбор конкретных вопросов.** На экране «Вопросы» пользователь отмечает любые вопросы галочками (поиск, фильтры по категории, сложности и закладкам) и сохраняет их как набор. Набор можно создать и из списка закладок.

**Сохранённый набор:** название, режим, фиксированный список вопросов в порядке `position`. Каждая игра с набором использует ровно эти вопросы. Диапазон, категории, сложность и «повторять» на набор не действуют. Один вопрос может входить в несколько наборов. Правка текста вопроса набор не меняет; удаление вопроса администратором убирает его из набора и создаёт уведомление пользователю. Порядок в наборе фиксированный (допущение).

**Правило «без повторов».** Учитывается любой ответ, верный или неверный, но только в том режиме, где правило включено. Отвеченными считаются вопросы с ответами пользователя в этом режиме не раньше `cycle_started_at`. Когда пул исчерпан, при следующем старте `cycle_started_at` сбрасывается на текущий момент и выводится сообщение «Все вопросы пройдены, начинаем сначала». История ответов не удаляется. Если в пуле осталось меньше вопросов, чем нужно игре, игра берёт оставшиеся и становится короче.

**Недостаток вопросов.** Если в пуле меньше вопросов, чем нужно режиму, игра использует все доступные и показывает сообщение о сокращении.

**Закладки.** Пользователь ставит закладку на вопрос в любом режиме и в карточке ответа. Закладки хранятся по пользователю, а не по режиму. Экран «Закладки»: список, кнопка «Повторить в Карточках», создание набора из выбранных. Снятие закладки не удаляет историю ответов и не меняет созданные наборы.

## 7. Игровые режимы

**Общие правила.** Все варианты A–D показываются в случайном порядке для каждого показа вопроса; буква на экране не обязана совпадать с буквой в файле (в `answer.selected` пишется буква из файла). После ответа показываются правильный вариант, подсказка и мнемоника (если есть), кнопка «Закладка» и «Сообщить об ошибке». В конце игры запускается движок обратной связи (раздел 8). Минимальный размер шрифта — 16 px.

**7.1 Карточки.** Игра — колода из K карточек (по умолчанию 20) из пула. Лицевая сторона — вопрос; по нажатию переворот: правильный ответ (текст верного варианта), подсказка, мнемоника. Пользователь отмечает «знаю» или «не знаю» (самооценка; допущение: в этом режиме варианты A–D не используются). Карточки с «не знаю» возвращаются в колоду через 3–5 других карточек. Игра заканчивается, когда по каждой карточке есть отметка «знаю», либо по кнопке «Завершить». В процент и агрегаты входит только первая отметка по каждой карточке; повторы получают `is_repeat`.

**7.2 Доска.** Сетка 4×4 (допущение), за каждой плиткой вопрос из пула. Если вопросов меньше 16, плиток столько, сколько вопросов. Выбор плитки открывает вопрос с 4 вариантами. Ответ засчитывается, плитка закрывается независимо от результата. Игра заканчивается, когда открыты все плитки. Очков нет; итог — процент верных.

**7.3 Своя игра.** Столбцы — категории, строки — уровни сложности. Цена вопроса = уровень × 100 (уровень 2 — 200, 3 — 300, 4 — 400; при появлении уровней 1 и 5 — 100 и 500). Верный ответ добавляет цену, неверный отнимает её полностью (допущение); счёт может быть отрицательным. Таймера нет.

Состав доски:

- Категория допустима, если в пуле у неё не меньше 3 вопросов. Пользователь выбирает до 5 допустимых категорий; по умолчанию — 5 случайных допустимых.
- Ячейка (категория, уровень) создаётся, если в пуле есть хотя бы один такой вопрос; вопрос выбирается случайно, ячейки без вопросов не показываются. Из-за распределения сложности в текущей базе большая часть доски будет на уровнях 2 и 3.
- Игра заканчивается, когда открыты все ячейки.

**7.4 Викторина.** Игра — 10 вопросов (допущение; настройка 10 / 20 / 50). Вопрос с 4 вариантами, таймер 20 секунд. Верный ответ даёт базовые 1000 баллов (допущение): за первые 5 секунд — полный балл, далее линейно убывает до 500 к концу таймера. Неверный ответ или истёкший таймер — 0; по истечении таймера в `answer` пишется `selected = null`, `correct = нет`.

**Итоговый процент** для всех режимов = верные ответы / учтённые ответы × 100, округление до ближайшего целого, 0,5 округляется вверх.

## 8. Движок обратной связи

Движок запускается один раз при завершении игры и формирует до трёх сообщений: общий результат (всегда), слабая категория, слабый уровень.

**Вход.** Учитываемые ответы игры (в Карточках — первые отметки). N — их число.

**Шаг 0. Пустая игра.** Если N = 0, обратная связь не формируется, пользователю выводится «В этой игре нет ответов, итоги не сформированы».

**Шаг 1. Общий результат.** Процент (раздел 7), округлённый до целого, определяет tier:

| Tier | Процент |
| --- | --- |
| 1 | 0–20 |
| 2 | 21–40 |
| 3 | 41–60 |
| 4 | 61–80 |
| 5 | 81–100 |

Выбирается один шаблон из пула tier.

**Шаг 2. Слабая категория.** Категория слабая, если в игре по ней не меньше 3 ответов и верных меньше 50% (верных × 2 < ответов). Выбирается категория с наименьшим процентом; при равенстве — с большим числом ошибок; при равенстве — с меньшим id. Выбирается один шаблон категории.

**Шаг 3. Слабый уровень.** Уровень слабый по тому же правилу (не меньше 3 ответов, верных меньше 50%). Выбирается уровень с наименьшим процентом; при равенстве — с большим числом ошибок; при равенстве — высший уровень. Выбирается один шаблон уровня. Сообщение уровня отдельное, оно не вставляется в шаблон категории.

**Шаг 4. Ничего слабого нет.** Выводится только сообщение tier.

**Выбор шаблона** (для каждого вида): берутся шаблоны вида (и tier) с выполненным условием `requires`; из них исключаются показанные пользователю в последних 5 играх (любой режим); из оставшихся случайный. Если все исключены, исключение игнорируется.

**Условия `requires`:** `prev_game` — у пользователя есть предыдущая завершённая игра в этом режиме; `first_game` — это первая игра пользователя; `mode_quiz` — режим Викторина; `perfect` — 100% верных; `has_errors` — есть неверные ответы; `prev_weak_cat` — эта категория была слабой в предыдущей игре режима; `multi_scope` — в игре не менее двух категорий (для шаблонов уровней — не менее двух уровней).

**Шаг 5. Сохранение.** В конце игры записываются `game_aggregate` (по уровням и категориям) и `game_feedback` (шаблон, готовый текст и параметры). Текст сохраняется после подстановки, правка шаблонов позже на старые игры не влияет. При повторном открытии игры показывается сохранённое.

**Плейсхолдеры:** `{процент}`, `{верных}`, `{неверных}`, `{всего}`, `{прошлый_процент}`, `{среднее_время}` (сек, один знак), `{категория}`, `{кат_верных}`, `{кат_неверных}`, `{кат_всего}`, `{кат_процент}`, `{уровень}`, `{ур_верных}`, `{ур_неверных}`, `{ур_всего}`, `{ур_процент}`, `{худший_уровень}`.

## 9. Библиотека сообщений

Сообщения заранее написаны и хранятся в базе (`feedback_template`), загружаются из этого раздела при развёртывании. Правка шаблонов через интерфейс — вне версии 1. Тон нейтральный: одно наблюдение, без обращения, без советов и прогнозов. Каждое утверждение проверяется данными игры; шаблон с условием не показывается, если условие не выполнено.

**Tier 1 (0–20%)**

1. Верных ответов в этой игре: {процент}%.
2. Верно отвечено на {верных} из {всего} вопросов.
3. Большая часть вопросов этой игры осталась без верного ответа.
4. Результат игры — {процент}%: материал пока закреплён слабо.
5. Верных ответов меньше одной пятой от общего числа.
6. [first_game] Первая игра завершена с результатом {процент}%.
7. Неверных ответов в игре: {неверных} из {всего}.
8. Игра завершена с результатом {процент}%.
9. Основная часть материала этой игры пока не закреплена.
10. Верные ответы составляют меньшую часть результатов игры.

**Tier 2 (21–40%)**

1. {процент}% верных ответов: верные ответы есть, но их меньшинство.
2. Верно отвечено на {верных} из {всего} вопросов.
3. Неверных ответов в игре больше, чем верных.
4. Результат игры — {процент}%.
5. Закреплена меньшая часть материала этой игры.
6. [prev_game] Прошлая игра этого режима — {прошлый_процент}%, эта — {процент}%.
7. [mode_quiz] Среднее время ответа — {среднее_время} с, верных ответов — {процент}%.
8. Верных ответов — {верных}, неверных — {неверных}.
9. Игра завершена на уровне {процент}%.
10. Результат ниже половины верных ответов.

**Tier 3 (41–60%)**

1. Около половины ответов верные: {процент}%.
2. Верно отвечено на {верных} из {всего} вопросов.
3. Верных и неверных ответов примерно поровну.
4. Примерно половина материала этой игры закреплена.
5. [prev_game] Прошлая игра этого режима — {прошлый_процент}%, эта — {процент}%.
6. [mode_quiz] Среднее время ответа — {среднее_время} с.
7. Результат игры — {процент}%.
8. Неверных ответов в игре: {неверных}.
9. Материал этой игры закреплён примерно наполовину.
10. Средний результат: {процент}% верных ответов.

**Tier 4 (61–80%)**

1. Результат хороший: {процент}% верных ответов.
2. Верно отвечено на {верных} из {всего} вопросов.
3. Неверных ответов в игре: {неверных}.
4. Закреплена большая часть материала этой игры.
5. [prev_game] Прошлая игра этого режима — {прошлый_процент}%, эта — {процент}%.
6. [mode_quiz] Среднее время ответа — {среднее_время} с.
7. Верных ответов заметно больше, чем неверных.
8. Результат близок к высокому: {процент}%.
9. Игра завершена с результатом {процент}%.
10. Ошибок в игре меньше, чем верных ответов.

**Tier 5 (81–100%)**

1. Почти все ответы верные: {процент}%.
2. Верно отвечено на {верных} из {всего} вопросов.
3. [perfect] Все ответы в игре верные.
4. [has_errors] Неверных ответов в игре: {неверных}.
5. Подавляющая часть материала этой игры закреплена.
6. [prev_game] Прошлая игра этого режима — {прошлый_процент}%, эта — {процент}%.
7. [mode_quiz] Среднее время ответа — {среднее_время} с.
8. Результат игры — {процент}%.
9. [has_errors] Ошибок в игре немного: {неверных} из {всего}.
10. Материал этой игры закреплён на уровне {процент}%.

*Для tier 1 безусловных шаблонов 9, для tier 2–5 — не менее 6 в каждом.*

**Категории** (шаблон без условий, если не указано)

1. По теме «{категория}» верных ответов меньше, чем неверных.
2. По теме «{категория}» верно {кат_верных} из {кат_всего}.
3. По теме «{категория}» результат ниже остальных.
4. Тема «{категория}» имеет самый низкий процент верных ответов в этой игре.
5. По теме «{категория}» неверных ответов: {кат_неверных} из {кат_всего}.
6. Верных ответов по теме «{категория}» менее половины.
7. Тема «{категория}» закреплена слабее остальных.
8. [prev_weak_cat] Тема «{категория}» была слабой и в прошлой игре этого режима.
9. Результат по теме «{категория}»: {кат_процент}%.
10. Тема «{категория}» дала больше всего неверных ответов в этой игре.

**Уровни сложности**

1. На вопросах уровня {уровень} верных ответов меньше половины.
2. Уровень {уровень}: верно {ур_верных} из {ур_всего}.
3. Результат на уровне {уровень} ниже, чем на остальных.
4. Вопросы уровня {уровень}: {ур_процент}% верных ответов.
5. Больше всего неверных ответов — на вопросах уровня {уровень}.
6. Уровень {уровень} закреплён слабее остальных.
7. На уровне {уровень} неверных ответов больше, чем верных.
8. Вопросы уровня {уровень} дали {ур_неверных} неверных ответов.
9. Результат по уровню {уровень} ниже 50%.
10. Уровень {уровень} — слабое место этой игры.

Шаблоны категорий 3, 4, 7, 10 и уровней 3, 5, 6, 10 сравнивают с остальными, поэтому имеют неявное условие `multi_scope`: в игре есть не менее двух категорий (для уровней — двух уровней). Иначе они не выбираются. 
## 10. Аналитика

Период: 7 / 30 / 90 дней / всё время; по умолчанию 30. Период применяется ко всем четырём блокам. Дни считаются по часовому поясу `Asia/Tashkent` (допущение, настройка сервера).

- **Чаще всего ошибочные вопросы** — таблица из 20 строк: № и текст вопроса, категория, уровень, число ошибок, доля ошибок, дата последней ошибки (ДД.ММ.ГГГГ). В таблицу попадают вопросы не менее чем с 2 ответами за период. Сортировка: доля ошибок, затем число ошибок. Дата последней ошибки берётся из `answer.answered_at`.
- **Активность по дням** — линейный график числа ответов по дням выбранного периода; дни без игр отмечены нулём и подписаны.
- **Режимы игры** — столбчатая диаграмма: число игр по каждому из четырёх режимов за период.
- **Динамика по категориям** — процент верных ответов по неделям. На графике не более 5 категорий (по умолчанию 5 с наибольшим числом ответов, остальные добавляются галочкой); недели с менее чем 3 ответами по категории — разрыв линии.

## 11. Админ-панель и отчёты об ошибках

Доступ только для роли «админ» (раздел 5).

- **Импорт.** Загрузка файла в формате раздела 3, предпросмотр различий, применение, журнал ошибок строк.
- **Вопросы.** Список с поиском и фильтрами; правка текста, вариантов, правильного ответа, категории, сложности, подсказки, мнемоники; скрытие и восстановление (мягкое удаление). Следующий импорт может перезаписать правки, поэтому перед применением показывается предупреждение о строках, изменённых вручную.
- **Категории.** Переименование и объединение; удаление только для категорий без вопросов. При объединении `category_id_at_answer` в старых ответах не меняется, агрегаты завершённых игр остаются прежними.
- **Отчёты пользователей.** Кнопка «Сообщить об ошибке» в каждом режиме и на экране вопроса. Отчёт: вопрос, комментарий, статус «новый / в работе / исправлен / отклонён», заметка админа.
- **Пользователи.** Список, роли, дата последнего входа, число игр. Без доступа к содержимому личных данных, кроме имени и статистики.

## 12. Нефункциональные требования и стек

- **Язык и формат:** русский; даты ДД.ММ.ГГГГ, числа в русской локали.
- **Производительность:** открытие вопроса или карточки менее 300 мс, формирование итогов игры менее 1 с при 300 вопросах и до 100 пользователей, до 10 одновременных игр (допущение).
- **Безопасность:** доступ к админ-панели только по роли; принятый риск входа без пароля — раздел 5; ввод валидируется на сервере; клиент не получает правильный ответ до того, как ответ отправлен (в Викторине, Доске и Своей игре).
- **Персональные данные:** хранится только имя и статистика; если имена реальные, проверить требования законодательства о персональных данных страны размещения.
- **Доступность:** адаптивная вёрстка для ноутбука и планшета; шрифт не менее 16 px в играх; управление клавишами (A–D, пробел для переворота); контраст по WCAG AA.
- **Стек (предварительно, к подтверждению):** React, Node.js, PostgreSQL (при такой нагрузке допустим SQLite). Фоновая очередь и ключи ИИ не нужны.
- **Хостинг и копии:** одна виртуальная машина или платформа с управляемой базой; ежедневная резервная копия, проверка восстановления перед запуском. Где хостить — решает заказчик (раздел 14).

## 13. Критерии приёмки

1. Импорт `CorpFin_300.xlsx` создаёт 300 вопросов и 20 категорий, на листе «Источники» — 20 источников; повторный импорт не создаёт дублей.
2. Вход: имя «Аня» и « аня » — один профиль; имя из 1 символа и из 31 символа отклоняется; для нового имени требуется подтверждение создания.
3. Без настроек игра берёт вопросы из всех 300; при диапазоне 10–20 только №10–20; при диапазоне с 5 вопросами и Доске 4×4 плиток 5.
4. «Повторять — нет»: вопрос, отвеченный в Викторине, не выпадает в Викторине до исчерпания пула, но может выпасть в Карточках; после исчерпания показано «Все вопросы пройдены, начинаем сначала».
5. Сохранённый набор из 12 вопросов всегда даёт те же 12; удаление одного из них админом оставляет 11 и создаёт уведомление.
6. Викторина: верный ответ на 3-й секунде — 1000, на 12,5-й — 750, на 19,9-й — около 500; при истечении таймера — 0; неверный — 0.
7. Своя игра: верный ответ на вопрос уровня 3 даёт +300, неверный −300.
8. Движок (проверяется тремя примерами):
   - *Пример А.* Викторина, 10 ответов, верных 3 (30%, tier 2). Категория A: 4 ответа, 1 верный; B: 3, 1 верный; C: 3, 1 верный. Уровень 2: 6 ответов, 3 верных; уровень 3: 4 ответа, 0 верных. Ожидается: сообщение tier 2; слабая категория A (25%, самая низкая); слабый уровень 3 (0%; уровень 2 ровно 50% — не слабый). Итого три сообщения.
   - *Пример Б.* Доска, 10 ответов, 6 верных (60%, tier 3). Категории X и Y по 5 ответов, по 3 верных (60%). Уровень 2: 7 ответов, 5 верных; уровень 3: 3 ответа, 1 верный (33%). Ожидается: tier 3 и слабый уровень 3; слабой категории нет.
   - *Пример В.* 12 ответов, все верные. Ожидается: только сообщение tier 5, возможны шаблоны 1–3, 5, 8, 10, а также 6 и 7 при выполнении их условий; шаблоны с `has_errors` исключены.
   - *Пример Г.* 0 ответов: «В этой игре нет ответов, итоги не сформированы».
9. Итоги игры при повторном открытии совпадают с показанными в конце, даже если шаблон или вопрос потом изменили.
10. Правка уровня вопроса админом не меняет агрегаты и аналитику прошедших игр.
11. Аналитика: вопрос с одним ответом в таблицу ошибок не попадает; график активности за 30 дней содержит 30 точек.
12. Отчёт об ошибке виден админу в списке со статусом «новый».
